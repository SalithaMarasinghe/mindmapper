# SPEC-08: Offline Access & PWA

> **Status:** DONE

## Goal

Allow users to pin specific maps for offline access. When offline, the app must read all map data (meta, nodes, content) from IndexedDB instead of Supabase and silently block all write operations. Additionally, configure the app as an installable Progressive Web App with Workbox service worker precaching for static assets.

---

## Design / Technical Constraints

- **Offline storage:** `idb-keyval` package. Thin wrapper in `src/lib/offlineStore.ts`. Zustand store in `src/store/offlineStore.ts`.
- **Offline is strictly read-only:** No write queue. No sync-on-reconnect. Any write operation that fires while `navigator.onLine === false` must: (1) call `toast.error('Cannot [action] while offline')`, (2) return early — do NOT queue or retry. This applies to ALL write methods in `mapStore`, `mapsStore`, and `contentStore`.
- **Snapshot model:** Offline snapshots are point-in-time. They do NOT sync back to Supabase. The user must manually toggle offline access to refresh the snapshot.
- **IndexedDB key schema:**
  - `'offline_maps'` → `string[]` (list of pinned map IDs)
  - `'map_meta_{mapId}'` → `MindmapMeta`
  - `'map_nodes_{mapId}'` → `MindmapNode[]`
  - `'map_content_{mapId}'` → `Record<string, NodeContent>`
- **PWA configuration:** `vite-plugin-pwa` with Workbox. Cache name: auto-generated by Workbox. Strategy: `autoUpdate` (service worker updates automatically). Precache limit: 5MB. Do NOT cache Supabase API responses — only static build assets.
- **Dev environment:** In `main.tsx`, when `import.meta.env.PROD === false`, call `navigator.serviceWorker.getRegistrations()` and unregister all registrations, then call `caches.keys()` and delete all caches. This prevents Workbox from serving stale files during development.
- **All Zustand stores must have offline fallback paths.** `mapStore.loadMap()`, `mapsStore.fetchMaps()`, and `contentStore.loadContent()` must each check `navigator.onLine` before calling Supabase and fall back to their respective IndexedDB read methods.

## Implementation Steps

### `src/lib/offlineStore.ts`
- Import `get`, `set`, `del` from `idb-keyval`
- Export a plain object `offlineStore` with methods (not a Zustand store — this is the raw IndexedDB layer):
  - `getOfflineMaps(): Promise<string[]>` — read `'offline_maps'` key
  - `isMapOffline(mapId): Promise<boolean>` — check if `mapId` is in `'offline_maps'` array
  - `saveMapOffline(mapMeta, nodes, content)` — write `map_meta_{id}`, `map_nodes_{id}`, `map_content_{id}`, update `'offline_maps'`
  - `removeMapOffline(mapId)` — delete the three keys, update `'offline_maps'`
  - `getMapMeta(mapId): Promise<MindmapMeta | undefined>`
  - `getMapNodes(mapId): Promise<MindmapNode[] | undefined>`
  - `getMapContent(mapId): Promise<Record<string, NodeContent> | undefined>`

### `src/store/offlineStore.ts`
- State: `offlineMapIds: string[]`, `isSyncing: boolean`
- Implement `initOfflineStore()`: load `offlineStore.getOfflineMaps()` and set `offlineMapIds`
- Implement `toggleOffline(mapId, mapMeta, nodes, content)`:
  - If currently offline: call `offlineStore.removeMapOffline(mapId)`, update `offlineMapIds`
  - If not offline: call `offlineStore.saveMapOffline(mapMeta, nodes, content)`, update `offlineMapIds`
  - Set `isSyncing` during the operation
- Implement `isMapOffline(mapId): boolean` — synchronous check of `offlineMapIds`

### `src/store/mapStore.ts` (update)
- In `loadMap(mapId)`: check `navigator.onLine`. If offline AND `offlineStore.isMapOffline(mapId)`: read from `offlineStore.getMapNodes()` and `offlineStore.getMapMeta()`. Set nodes and edge_waypoints from snapshot. Return.
- Add `navigator.onLine` guard and `toast.error` at the top of: `addNode`, `updateNode`, `deleteNode`, `saveNodePositions`, `saveBatchChanges`, `updateEdgeWaypoints`

### `src/store/mapsStore.ts` (update)
- In `fetchMaps()`: check `navigator.onLine`. If offline: read map IDs from `offlineStore.getOfflineMaps()`, then call `offlineStore.getMapMeta(id)` for each. Populate `maps[]` from snapshots.
- Add `navigator.onLine` guard to: `createMap`, `updateMap`, `deleteMap`, `duplicateMap`

### `src/store/contentStore.ts` (update)
- In `loadContent(mapId)`: check `navigator.onLine`. If offline: call `offlineStore.getMapContent(mapId)`. Populate `content` Record from snapshot.
- In `fetchNodeContent(nodeId, mapId)`: if offline and map is cached, return from IndexedDB.
- In `getOrCreateContent(nodeId, mapId)`: if offline and cached, return from IndexedDB. If offline and NOT cached, return `emptyContent()` — do not INSERT into Supabase.
- Add `navigator.onLine` guard to: `updateContent`, `markComplete`, `markIncomplete`

### `vite.config.ts` (update)
- Add `VitePWA` plugin from `vite-plugin-pwa`
- Config: `registerType: 'autoUpdate'`, `workbox: { maximumFileSizeToCacheInBytes: 5242880 }`
- Set `manifest` with app name, icons, `theme_color: '#0d9488'`, `background_color: '#0f1117'`, `display: 'standalone'`

### `src/main.tsx` (update)
- In `if ('serviceWorker' in navigator)`:
  - `PROD`: register `/sw.js` on `window.load` event
  - Not PROD: unregister all service workers + delete all caches

### UI for offline toggle
- Add an "Offline" toggle button to `CanvasToolbar` or `DashboardPage`
- Call `offlineStore.getState().toggleOffline(mapId, ...)` on click
- Show current offline status: icon changes to a cloud-slash when pinned
- Show `isSyncing` spinner during snapshot operation
